    How it works

    One monster, four organs

    Each part does one job and has no way to do the others' jobs. The Sentinel can't run L2 actions, the agents can't skip policy, and nothing reaches systemd without a human-signed token.

    ReflexesSentinel, in Go

    Watches PSI, cgroup v2 memory.events, and journald. On P1/P2 pressure it applies one reversible L1 reflex, such as memory.reclaim or a MemoryHigh throttle, with a TTL and a persistent rollback.

    internal/sentinel · internal/reflex

    BrainA Kiro Crew

    franken-conductor wakes on wa-bridge webhooks and spawns specialists: the Sentry triages, the Architect writes a plan, the Remediator asks for approval and then executes.

    app.json · .kiro/agents

    HandsA policy gate

    Every plan is checked against policy/actions.yaml: allowlisted actions only, protected units and PID 1 refused, targets kept inside the incident's cgroup. Each step needs its own single-use Ed25519 token.

    internal/policy · internal/approval

    ConscienceWhatsApp approval

    wa-bridge sends a poll to allowlisted admins. A vote mints one token per plan step. Afterwards the Sentinel watches memory and PSI for a forward window before it closes the incident or escalates.

    Built with Kiro

    Every organ came out of a spec

    Kiro drove the build from requirements to property tests, and Kiro Crew runs the agents in production. Every card links to the file that does the work.

    Specs

    EARS requirements to property tests

    Twelve requirements, a design with correctness properties P1 to P4, and a task list. The properties became property-based tests with pgregory.net/rapid.

    .kiro/specs/server-incident-remediation/     Steering

    Rules that load when they matter

    Product, tech, structure, and project rules load on every turn. linux-kernel.md loads only while editing the PSI, cgroup, and kernelfs packages; the incident runbook loads on request.

    .kiro/steering/     Hooks

    Guards on the agent's own hands

    A PreToolUse hook pipes every franken-sentinel and franken-wa MCP call through franken guard --audit, which records a redacted audit row and exits 2 to block a protected target. File-save hooks re-test the executor, policy catalog, and redaction code, and a Stop hook runs vet and the full suite.

    .kiro/hooks/     MCP

    Two MCP servers, one trust boundary

    franken-sentinel serves tools such as incident_claim, plan_submit, action_execute, and verify_health over Streamable HTTP with bearer auth. franken-wa adds wa_request_approval.

    internal/mcpserver · internal/wabridge     Kiro Crew app

    A conductor and three specialists

    app.json ships four agents, three skills, both MCP servers, an incident sweep and a morning digest cron, and this Graveyard as a dashboard page.

    app.json · .kiro/agents/     Skills

    Know-how on demand

    linux-memory-forensics, remediation-runbooks, and incident-spec-writer load only when a specialist needs them, which keeps every agent's context small.
