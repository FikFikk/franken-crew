    How it works

    One monster, four separated organs

    Each component owns one strict trust boundary and cannot bypass another. The Sentinel never runs L2 restarts alone, agents cannot invent shell commands, and systemd waits for a human-signed Ed25519 vote.

    01 · Reflexes

    Go Kernel Sentinel

    Polls /proc/pressure/memory, cgroup v2 memory.events, and journald at 1 Hz. On P1/P2 thrashing it applies one reversible L1 reflex—cgroup_reclaim (bounded at 200 ms with in-flight deduplication) or runtime MemoryHigh throttle—with automatic TTL rollback and vanished-unit reconciliation.

    < 250 ms budget TTL auto-rollback internal/sentinel · internal/reflex
    02 · Brain

    4-Agent Kiro Crew

    franken-conductor wakes on webhooks and orchestrates three specialists: franken-sentry captures redacted telemetry, franken-architect writes a canonical SHA-256 plan, and franken-remediator drives WhatsApp approval and L2 steps.

    Webhook + 15m sweep app.json · .kiro/agents/
    03 · Hands

    Policy & PreToolUse Gate

    Every plan is validated against policy/actions.yaml: allowlisted tools only, PID 1 and critical units (ssh, systemd-journald, tailscaled, franken-bridge) permanently protected, and MCP calls audited by franken guard --audit.

    Single-use JTI internal/policy · internal/approval
    04 · Conscience

    WhatsApp Approval & Forward Verification

    wa-bridge delivers a Native Poll (with deterministic short-code fallback) to allowlisted admin JIDs, mints one unique Ed25519 token per approved step, and monitors a 120 s forward verify_health observation window before rolling back L1 limits and writing a secret-redacted postmortem.

    120 s verify window Secret-redacted markdown cmd/wa-bridge · verify_worker.go

    End-to-End Closed Loop Execution Sequence

    1. PSI & cgroup spike
    2. Sub-250 ms L1 reflex
    3. SSE / Webhook triage
    4. SHA-256 policy plan
    5. WhatsApp poll
    6. Ed25519 per-step tokens
    7. 120 s forward verify
    8. Redacted postmortem

    Architecture & Trust Boundaries

    Three planes, zero unverified mutations

    Kernel telemetry and Bearer-protected MCP endpoints stay inside Tailscale or loopback boundaries while human authorization arrives asynchronously via WhatsApp.

    Plane A · Kernel & Daemon franken sentinel serve

    Deterministic Reflex & MCP

    • Polls PSI + cgroup v2 every 100 ms–1 Hz with linear TTO forecasting over a 60 s slope.
    • Bounds kernel memory.reclaim writes to 200 ms with in-flight deduplication so swap storms never stall goroutines.
    • Reconciles vanished transient *.service units every tick and captures single-process OOM kills via memory.events.
    • Serves Streamable HTTP POST /mcp and GET /v1/events SSE with automatic cursor reset on restart.
    Plane B · Kiro Crew app.json · preToolUse

    Event-Driven Agent Triage

    • franken-conductor wakes immediately via webhook on incident.opened and vote grant, backed by a 15 m sweep cron.
    • franken-sentry executes read-only L0 tools (node_snapshot, cgroup_top, journal_tail, process_tree).
    • franken-architect submits steps to plan_submit (max 2 revisions) to lock a canonical SHA-256 plan_hash.
    • Every MCP tool invocation passes franken guard --audit before reaching Sentinel.
    Plane C · Human Bridge cmd/wa-bridge

    Headless WA & Ed25519

    • Single owner of the whatsmeow SQLite session; syncs node identity dynamically from Sentinel health and SSE streams.
    • Sends redacted incident alerts under 2 s and builds Native Poll options strictly from policy-validated plan labels + text-code fallback.
    • Signs single-use per-step Ed25519 tokens bound to plan_hash + step_id + action + target with mode-0600 key isolation.
    • Runs a 15 s × 3 Sentinel heartbeat watcher so silent node crashes trigger out-of-band WhatsApp alerts.

    Policy & Safety Guarantees

    Allowlisted action tiers & formal invariants

    Neither autonomous LLMs nor prompt injections embedded in system logs can bypass the explicit contract in policy/actions.yaml.

    L0 · Observe

    Forensic Telemetry

    Read-only inspection with secret & phone number redaction applied before SQLite persistence or LLM context.

    node_snapshot psi_history cgroup_top journal_tail process_tree zombie_report incident_claim
    L1 · Reflex

    Reversible Pressure Relief

    Executed deterministically inside 250 ms without dropping PIDs; restored automatically via TTL or health verify pass.

    cgroup_reclaim cgroup_throttle admission_close
    L2 · Mutate

    Human-Signed Recovery

    Gated on an accepted plan, an allowlisted WhatsApp vote, and an unexpired single-use Ed25519 signature per step.

    unit_restart pm2_reload pm2_restart_instance process_terminate zombie_reap
    L3 · Forbidden

    Absolute Prohibitions

    Rejected in Go policy, schema validation, and franken guard PreToolUse hook (exit 2) — even with a human token.

    raw_shell file_delete power_action persistent_config global_drop_caches modify_memory_max
    P1 · Latency Bound

    L1 reflexes complete within the 250 ms SLA without blocking goroutines on slow disk or swap reclaim.

    P2 · Replay Immunity

    Every Ed25519 token is single-use via atomic SQLite JTI consumption, step-bound, and TTL-expired.

    P3 · Protected Targets

    PID 1, ssh/sshd, systemd-journald, tailscaled, Sentinel, and franken-bridge remain untouchable.

    P4 · L1 Reversibility

    Each L1 throttle persists the prior MemoryHigh setting and restores it automatically with retry backoff.
