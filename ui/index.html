    How it works

    One monster, four separated organs

    Each component owns one strict trust boundary and cannot bypass another. The Sentinel never executes L2 restarts autonomously, the AI crew cannot invent shell commands outside policy/actions.yaml, and systemd never mutates without a human-signed Ed25519 token.

    01 · ReflexesGo Kernel Sentinel

    Polls /proc/pressure/memory, cgroup v2 memory.events, and journald at 1 Hz. On P1/P2 pressure it applies one reversible L1 reflex—cgroup_reclaim (bounded at 200 ms) or MemoryHigh throttle—with TTL auto-rollback and vanished-unit reconciliation.

    internal/sentinel · internal/reflex

    02 · Brain4-Agent Kiro Crew

    franken-conductor wakes on webhooks and orchestrates three specialists: franken-sentry collects redacted telemetry, franken-architect submits a canonical SHA-256 remediation plan, and franken-remediator requests human vote and triggers L2 steps.

    app.json · .kiro/agents/

    03 · HandsPolicy & Token Gate

    Every plan is validated against policy/actions.yaml: allowlisted actions only, PID 1 and critical system units (sshd, systemd-journald, tailscaled, franken-bridge) refused, and every L2 step verifies a single-use Ed25519 signature.

    internal/policy · internal/approval

    04 · ConscienceWhatsApp & Verify

    wa-bridge delivers a Native Poll (+ deterministic text-code fallback) to allowlisted admins, mints per-step tokens on vote, and monitors a 120 s forward verify_health window before rolling back L1 limits and writing a redacted postmortem.

    cmd/wa-bridge · verify_worker.go

    Architecture & Trust Boundaries

    Three planes, zero unverified mutations

    Telemetry stays inside your private Tailscale or loopback boundary while human decisions arrive asynchronously over end-to-end encrypted WhatsApp.

    Plane A · Kernel & Daemon franken sentinel serve

    Deterministic Reflex & MCP Server

    • Polls PSI + cgroup v2 every 100 ms–1 Hz with linear TTO forecasting over a 60 s least-squares slope.
    • Bounds kernel memory.reclaim to a 200 ms write timeout with in-flight deduplication so overloaded disks never stall goroutines.
    • Reconciles vanished transient *.service units every rediscovery tick and captures single-process OOM kills via memory.events:oom_kill.
    • Exposes Bearer-protected Streamable HTTP POST /mcp, GET /v1/events SSE (auto-cursor reset), and SQLite WAL state.
    Plane B · Kiro Crew app.json · preToolUse

    Event-Driven Agent Investigation

    • franken-conductor wakes immediately via webhook on incident.opened (TRIAGE) and vote approval (EXECUTE), backed by a 15 m cron sweep.
    • franken-sentry runs read-only L0 tools (node_snapshot, cgroup_top, journal_tail, process_tree) with secrets pre-redacted.
    • franken-architect submits steps to plan_submit (max 2 revisions) to compute a canonical plan_hash (SHA-256).
    • Every MCP tool call passes through the PreToolUse hook running franken guard --audit before touching Sentinel.
    Plane C · Human Bridge cmd/wa-bridge

    Headless WhatsApp & Ed25519 Signing

    • Single owner of the whatsmeow SQLite session; receives real-time Sentinel SSE events and syncs node identity dynamically.
    • Sends rich incident alerts in < 2 s and builds WhatsApp Poll options strictly from policy-validated plan labels + text-code fallback.
    • Holds the Ed25519 private key (0600) and mints one unique jti token per plan step (plan_hash + step_id + action + target).
    • Runs a 15 s × 3 Sentinel heartbeat watcher so silent node crashes trigger an out-of-band WhatsApp alert automatically.

    Policy & Safety Guarantees

    Allowlisted action tiers & formal invariants

    No agent—and no compromised prompt inside journald logs—can escalate privileges beyond the explicit contract in policy/actions.yaml.

    Tier L0 · Observe Autonomous Read-Only

    Forensic Telemetry

    Read-only host inspection with automatic redaction (sk-..., phone numbers, bearer tokens) before storage or LLM context.

    node_snapshot psi_history cgroup_top journal_tail process_tree zombie_report incident_claim
    Tier L1 · Reflex Autonomous · Reversible TTL

    Immediate Pressure Relief

    Triggered deterministically by Go Sentinel within 250 ms to buy headroom without dropping processes; auto-rolled back when TTL expires or verification passes.

    cgroup_reclaim cgroup_throttle admission_close
    Tier L2 · Mutate Requires Human Ed25519 Vote

    Signed Service Recovery

    Requires a submitted plan, human WhatsApp vote from an allowlisted admin JID, and an unexpired single-use Ed25519 token bound to step + target.

    unit_restart pm2_reload pm2_restart_instance process_terminate zombie_reap
    Tier L3 · Forbidden Hard-Blocked Everywhere

    Absolute Prohibitions

    Rejected in Go policy engine, schema validator, and franken guard PreToolUse hook (exit 2) — even with a human token.

    raw_shell file_delete power_action persistent_config global_drop_caches modify_memory_max
    P1 · Latency BoundL1 reflex completes within 250 ms budget without blocking on slow swap/disk reclaim.
    P2 · Replay ImmunityEach Ed25519 token is single-use (atomic SQLite JTI consume), step-scoped, and TTL-bound.
    P3 · Protected-Target SafetyPID 1, ssh/sshd, systemd-journald, tailscaled, Sentinel, and franken-bridge are untouchable.
    P4 · L1 ReversibilityEvery L1 throttle records prior MemoryHigh and auto-restores with backoff retry.
