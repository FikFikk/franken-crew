# FrankenCrew demo video: script and shot list

Target length: **2:50**. The rules say judges do not have to watch past 3:00, so the last frame with the URL
must land before that.

The video is built in code with Remotion in [`apps/video/`](../apps/video/) (design in
[REMOTION_VIDEO.md](REMOTION_VIDEO.md)). It reads the narration column of the shot list below through
`npm run data`, so edit the narration here. The committed voiceover is synthesized from this narration with
Kokoro-82M (`npm run vo`); to use your own voice instead, record the seven paragraphs, run `npm run captions`,
and render. The steps are in [apps/video/README.md](../apps/video/README.md).

## What the rules require

From the [Kiroween 2026 official rules](https://kiroween.devpost.com/rules):

- Shorter than three minutes.
- Uploaded to **YouTube** and set to **Public**. The rules name YouTube only, not Vimeo. Unlisted may not count
  as publicly visible, so use Public.
- Footage of the project running on the platform it was built for (Linux, the browser, Kiro Crew).
- No third-party trademarks, copyrighted music, or other material you do not have permission to use. Record
  without music, or use a track from the YouTube Audio Library that allows reuse.
- In English, or with an English translation. Upload English captions; the narration below can be pasted in as
  a transcript.

The Presentation score asks four things: does the video show the project working end to end, does it say what
problem is solved and for whom, is it easy to follow, and is it memorable. The script answers them in that
order.

## Footage

The Remotion project already contains everything it shows:

- `apps/video/public/footage/graveyard-replay-broll.webm` (1280x720, 89 seconds, no audio), recorded with the
  Playwright power from the live site: the hero, the heap leak replay, its phone panel, the prompt injection
  replay, and its event log. YouTube and every common editor accept `.webm` if you want to cut it by hand.
- The event log screenshot of the prompt injection incident, the logos, and live output of the property
  tests, the chaos suite, and `franken guard`, all regenerated by `npm run data`.

Two optional recordings make the video stronger, because they show the project outside the simulation. Drop
them into `apps/video/public/footage/` and the video uses them automatically:

1. `phone-poll.mp4`: your phone screen with a real FrankenCrew poll from a paired wa-bridge, phone numbers
   blurred. It replaces the generated phone in the heap leak scene.
2. `crew-dashboard.mp4`: the Graveyard page inside the Kiro Crew dashboard. It appears in the Crew app scene.

## Shot list and narration

About 380 words, which fits 2:50 at 120 to 150 words per minute. Read it aloud once with a timer and cut a sentence if you run
long. Change any wording that does not sound like you.

| Time (at budget) | Scene in `apps/video` | Narration |
|---|---|---|
| 0:00 to 0:14 | S1: running clock and the memory and PSI chart of the heap leak | It's 3 a.m. A service on a small Linux server is leaking memory. In about two minutes the OOM killer will pick a victim, and nobody is on call. |
| 0:14 to 0:32 | S2: three cards (Sentinel, Kiro Crew, Human), the links between them, IT'S ALIVE | FrankenCrew stitches together three parts that were never meant to fit. A Go daemon, the Sentinel, handles reflexes in milliseconds. A Kiro Crew of four AI agents does the thinking. And a WhatsApp poll keeps a human in charge of anything that can't be undone. |
| 0:32 to 1:18 | S3: Graveyard footage time-warped to the narration, a six-step rail, the poll on a phone | This replay comes from the real engine, driven against a simulated cgroup. Pressure crosses ten percent, and the Sentinel opens an incident with two minutes left before OOM. Less than a millisecond later it applies one reversible reflex: a bounded memory reclaim with a timer to undo it. No model is involved. Then the Crew wakes up. The Sentry triages, the Architect writes a plan, and the Sentinel checks it against the policy. The plan arrives as a WhatsApp poll. The admin votes, the bridge signs a single-use token for that one step, and only then does the reload run. The Sentinel watches for 120 seconds and writes the postmortem. |
| 1:18 to 1:46 | S4: the injected log line, then the event log with three stamps | What if an agent is wrong, or tricked? Here a log line tells the operator to restart ssh.service. And a replayed approval token is refused, because its nonce was already used. |
| 1:46 to 2:22 | S5: spec, property tests, steering, hook with a real guard run, merged pull requests | I built FrankenCrew with Kiro, spec first. Twelve requirements in EARS form, a design with four properties that must never break, and 52 tasks. Each property became a property-based test, like "a token for plan X never authorizes plan Y". Steering loads the kernel rules only when Kiro edits kernel code. A PreToolUse hook sends every call to the FrankenCrew MCP tools through the same guard the agents meet in production. The audit and hardening rounds ran in Kiro Web, and each one came back as a pull request. |
| 2:22 to 2:38 | S6: the `app.json` card and the 20-run chaos terminal | The whole thing installs as a Kiro Crew app: four agents, two crons, two MCP servers, and this Graveyard as a dashboard page. Twenty chaos runs across five failure types: twenty passes. |
| 2:38 to 2:50 | S7: logo, tagline, URL, repository | FrankenCrew. Reflexes in Go, thinking in Kiro, and a human with the last word. Replays at frankencrew dot fikfikk dot my dot id. |

## Upload checklist

- Title: `FrankenCrew: kernel reflexes, a Kiro Crew, and a WhatsApp vote (Kiroween 2026)`
- Visibility: **Public**. Audience: not made for kids.
- Description:

  ```text
  FrankenCrew keeps small Linux servers alive. A Go Sentinel applies one reversible reflex within 250 ms of a
  memory incident, a Kiro Crew of four agents triages it and writes a plan, and nothing irreversible runs until
  an admin votes in a WhatsApp poll that mints a single-use Ed25519 token.

  Built with Kiro for the Kiroween 2026 hackathon (Frankenstein category).

  Live replays: https://frankencrew.fikfikk.my.id
  Code (MIT): https://github.com/FikFikk/franken-crew

  The replays shown are simulations through the real engine and are labelled as such in the UI.
  Narration voice: Kokoro-82M (Apache-2.0), synthesized locally.
  ```

- Captions: upload `apps/video/out/frankencrew-demo.srt` (from `npm run srt`) under Subtitles, English.
- Thumbnail: upload `apps/video/out/thumbnail.png` (from `npm run thumbnail`).
- After upload, open the link in a private window to confirm it plays without signing in, then paste it into
  the Devpost form and into `docs/DEVPOST_SUBMISSION.md`.
